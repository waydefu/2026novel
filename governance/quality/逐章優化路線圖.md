# 逐章優化路線圖｜2026-10-22 起

依作者指示：Ch8 完成後，現行正文每一章都用同一條 pipeline 重新優化。這份檔是該工作的施工路線與進度表。

## 為什麼要重做已定稿的章

第一次實測（Ch8）證明兩件事：

1. **機械掃描不足以判斷一章好不好。** Ch8 詞庫命中 0、硬閘門 0、契約 0 違規，但盲讀仍指出 4 處「演出完再補一句解釋」——那正是 AGENTS §5 STYLE-03／AI-02 與 09 明令禁止的東西。
2. **盲讀會直接抓到已定稿章的既有問題。** Ch8 的對照組 Ch4 被評閱者指出：現代網文式自嘲（「作品裡通常會更誇張。」）、機械編號平行句（「第一次…第二次…第三次…」連用兩次）、老師替讀者總結原理（「只代表通過得多，不代表控制得好。」）、少年替世界下判語（「好吧，魔法比遊戲技能麻煩多了，也有趣多了。」）、清單式並列開場、缺前文錨點。

結論：Ch1–Ch7 需要的是同一輪「解釋層清理＋盲讀比較」，不是重新設計。

## 每章標準流程（與 Ch8 相同）

1. **讀**：該章 + 必要 Canon（角色 Bible 該角色頁、11 的 State Diff 該章、09 對應章、相鄰章收尾）。
2. **v1**：以現行文字為底稿做第一輪修訂（只做 R1 行文層：解釋層清理、稱謂、資訊順序、節奏；不動事件、Knowledge、章末狀態）。
3. **機械掃描**：hard-gate／canon-contract／lexicon／rhythm／style-profile，全部只當候選。
4. **自冷讀**：五問（像不像 AI 交作業／角色是否在替作者整理邏輯／太乾太規矩太平均／有沒有想讀下去的慾望／哪個細節只有這個角色會有）。
5. **盲讀**：新舊兩版去標記、長度對齊，交給**無上下文**的評閱者，五維度各 1–5 分＋三項定性（AI 感／作者整理邏輯／角色專屬細節）。評閱者不得知道哪份是新稿。
6. **v2+**：依盲讀結果修訂，記錄返工次數與每一輪的觸發來源。
7. **同步**：11（State Diff／Knowledge 若有變）、必要時 09；`governance/quality/` 留一份該章的盲讀比較紀錄；`governance/provenance/` 留溯源。
8. **合併**：每章一個 PR，manifest 標 R1（只改行文，11 不動時用 `state_change: none`）或 R2（動到章末狀態時）。

## 每章的固定紀錄

- `governance/quality/YYYY-MM-DD_ChNN_盲讀比較.md`
- `governance/provenance/YYYY-MM-DD_ChNN_<章名>.md`（含溯源與三件套）

## 規則

- 每章一個 PR；不得為了「一次做完」把多章塞進同一個變更（跨章修改會讓 drift 與契約檢查失去意義）。
- 修章不得改事件、Knowledge 邊界、章末狀態；要改就升 R3 並單獨授權。
- 盲讀評閱者每次用**新的無上下文代理**，且不得由寫稿者自己擔任。
- 若盲讀結果與自冷讀衝突，以盲讀為準（自冷讀有作者偏見），但仍需人工判斷是否為評閱者誤讀。
