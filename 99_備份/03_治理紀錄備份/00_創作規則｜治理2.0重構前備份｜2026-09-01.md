# 00｜PROJECT WRITING GUIDE

## 《2026西幻小說》小說正文修稿必守規則・文件導航・施工與 QA

STATUS：ACTIVE

本文件是《2026西幻小說》的現行根規則，也是修改小說正文時必須遵守的規則範本。它約束讀取、判斷、修稿與驗收，不是要複製進正文的內容。

使用本範本時，先讀目標章節與最新權威來源，再修改正文；不得只憑本文件、舊稿或模型記憶補寫未確認內容。

# 0｜QUICK START

正文預設：繁體中文白話文＋第三人稱限知為主、第一人稱為輔的多 POV＋日式輕小說氣質的西幻世界。

最高目標：自然、清楚、像真人、符合角色。不要為了「像小說」變得抽象、文藝、哲理、華麗或生硬書面。

## 每次修改正文前

- 確認目標章節、最新施工稿、POV、時間、地點與場景目的。

- 讀現行根規則、任務所需 Canon 與正文最新版本，不從舊版或匯出副本施工。

- 確認誰知道什麼、誰不知道什麼、哪些只是猜測，以及資訊第一次出現的位置。

- 分清楚這次是行文修訂、場景重寫，還是 Canon 變更；未獲授權不得把修稿變成設定改寫。

- 先讓場景因果與人物選擇成立，再做中文、角色、Canon、時代語體與格式 QA。

- 有硬性 Fail 就修改；完成後必須重新讀整章，再做一次不看規則表的自由冷讀。

一句話文風：能用正常白話講清楚，就不要故意寫深。

一句話 POV：全書約六成第三人稱限知、四成第一人稱；同一場景只用一種人稱，並待在一個焦點角色的認知範圍內。

一句話反 AI：不要讓作者跳出來替角色解釋，也不要把自然寫法做成新模板。

一句話資訊順序：帶有「前面已發生」前提的詞，只能在前提已經成立後使用。

# 3｜DEFAULT NARRATIVE CONFIG

- LANGUAGE：繁體中文白話文。

- GENRE：日式輕小說氣質的中世紀感西幻。

- POV：第三人稱限知為主、第一人稱為輔；全書目標約六比四。

- SCENE：一個完整場景一個 POV；切換用章節或明確場景分隔。

- LENGTH：不再套用全書統一的 2,000～3,000 字。章長依作者最新明確指示與現行章綱中已由作者重新確認的章別目標執行；兩者衝突時以作者最新指示為準。不得為了舊的通用字數硬砍完整場景。

- FORMAT：正文使用 Google 文件原生「文件分頁（Tabs）」管理章節，每章一個獨立分頁。讀者可見的正文章節統一命名為「第一章｜章名、第二章｜章名……」，不得再以 P-01／P-02 作為正文顯示名稱；P01／P02 等編號只保留給大綱、場景卡與施工記錄作內部索引。若目前沒有實際序章正文，不建立只有章名的空白序章分頁。保留正文最新版本的章名、分段、空行、標點、編碼與換行格式；不得再用原生換頁符號或連續空行模擬章節分頁。

- STYLE ORDER：看得懂 ＞ 像真人 ＞ 準確 ＞ 順口 ＞ 有畫面 ＞ 修辭。

章長不足或超出目標時，先檢查場景是否缺事件、選擇、因果或必要反應。只能靠裝飾性景物、重複解釋或空泛內心戲補足的字數，不算完成。

# 4｜BEFORE EDITING：SCENE CARD ＆ INFORMATION MAP

正式修改前只保留最小場景卡：

- POV：採第三人稱限知或第一人稱；標明焦點角色，第一人稱時再註明誰在說「我」。

- 時間／地點：現在在哪、正在做什麼。

- WANT：此刻最直接想完成什麼。

- OBSTACLE：什麼讓它不順利。

- KNOWLEDGE：現在知道什麼、不知道什麼、只是懷疑什麼。

- CHANGE：場景結束時實際改變了什麼。

- RELATIONSHIP：關係前進、退後、誤解增加，或沒有變。

- EXIT：場景結束後下一步自然是什麼。

另外在場景卡或工作記錄標記資訊第一次出現的位置、每個角色能取得的證據，以及本場仍為 TBD 的內容。後文不能倒過來替前文補出本來不存在的前提，TBD 標籤也不能進入正文。

如果一場戲只有把設定講給讀者聽，沒有目標、阻礙、選擇或變化，不得直接進正文。

# 5｜THIRD-PERSON LIMITED + FIRST-PERSON MULTI-POV

5.1 全書以第三人稱限知為主、第一人稱為輔，篇幅目標約六比四。比例以全書與連續章節群衡量，不必每章硬切；仍以場景需要、角色聲音與閱讀節奏為先。

5.2 每場戲固定一種人稱與一名焦點角色。場內不得在第一、第三人稱之間游移，也不得跳進另一個人的內心；要切換時必須換場或明確分段。

5.3 第三人稱限知只能呈現焦點角色能感知、記得、推測或取得的資訊。別人的內心只能依動作、語氣與已知背景判斷，而且可以判斷錯。

5.4 第三人稱不等於全知，也不等於冷淡。禁止只把「我」換成角色名的假第三人稱；角色的尷尬、期待、吐槽、恐懼、心虛與被觸動仍要落在當下反應和選擇裡。

5.5 不論使用哪一種人稱，都要保留角色自己的語感與情緒密度。亞德里安的理性是處理問題的方法，不代表他沒有情緒，也不能被寫成只會計算的無感情機器。

5.6 使用第一人稱時，不代表每句都要有「我」。話題與施事者清楚時自然省略主語，也可以讓時間、物件、對方或眼前問題成為句首。

5.7 禁止把第三人稱稿機械改成「我做、我看、我想」，也少用「我看見／我聽見／我感覺到／我注意到／我意識到」等多餘感知外殼。連續三句以上都是「我＋動作／感受」時必須重組。

5.8 第一人稱禁止越界讀心與自我外部攝影機；不論人稱，都不能只為換句型而連續用「視線、手、腳步」充當鏡頭式主語，或形成身體部位主語鏈。

5.9 POV 切換後，前一至兩段內讓讀者知道焦點角色；第一人稱不要用「我是某某」自我介紹。同一事件原則上不從多 POV 重播，除非新視角增加決定、誤解、關係變化或關鍵資訊。

5.10 第一人稱不能變成長篇自我解說或心理報告。省略「我」後仍須讓施事者清楚；不能為避開「我」而寫出無主句、鏡頭式旁白或生硬倒裝。

- 亞德里安：先注意問題、矛盾、因果、成本與實用需求；有自知，但不自我診斷。前世帶有輕度二次元宅屬性，也會吐槽、覺得荒謬、興奮、尷尬、好奇或被審美戳中。外表安靜不等於內心沒反應。

- 克蕾西雅：先注意人際、資訊來源、利益、選擇、別人沒說的部分；可以誤判，不能全知。

- 艾琳娜：先注意現場、動作、身體狀態、現在能做什麼；陽光直接，但不是直覺測謊機。

# 6｜WHITE PROSE ＆ ANTI-AI

6.1 白話文是正式文風，不是退而求其次。普通話能準確講清楚，就不要升級成文藝句。

6.2 正文以語意完整的中文句子為骨架。碎句只在疼痛、驚愕、意識斷裂或真有節奏需求時使用。

6.3 禁止「一句一段＋短句連發」人工製造張力。張力來自人物目標、阻礙、時間壓力、失敗與資訊差。

6.4 同一動作鏈、同一話題可自然省略主詞；人物、焦點或施事者改變時再重新標明。

6.5 少用英文式外殼與銜接：因此、然而、與此同時、這意味著、某種程度上、基於這一點，以及「意識到／不得不承認／無法否認」的高頻套法。

6.6 避免歐化長定語、過多「的」、機械式「不僅…更…」「既…又…」「不是 X，而是 Y」。這些不是逐字禁用，而是不得形成生成慣性。

6.7 日輕是角色氣質與節奏，不是日文翻譯腔。不要高頻使用「果然、不愧是、真是拿你沒辦法」等套話。

6.8 一句話若換掉角色姓名就能原封不動塞進大量小說，優先檢查是否只剩泛用氣氛、抽象情緒或作者套式。

## 6A｜身體反應直接寫

- 身體反應優先寫具體可感知的生理狀況，不先用模糊比喻代替資訊。

- 「胸口像被什麼壓住」應依實際情境改成胸口發悶、吸氣不順、心跳變快、疼痛位置或其他具體反應。

- 「聲音變得很遠」若實際是耳鳴或聽不清，就直接寫耳鳴、嗡響或台詞聽不清。

- 視野發黑、手麻、耳鳴、呼吸不順等具體生理現象可以保留；它們不是空泛修辭。

- 比喻不是全面禁止。只有在意象具體、符合當下 POV 聲音，而且比直接描述多提供資訊時才保留。

## 6B｜資訊順序與前情預設詞

- 當「又、再次、依舊、果然、還是、和平常一樣、照例」用來表示重複、延續、恢復、符合預期或既有慣例時，才帶有前情前提。

- 每個具有上述語義的命中都要找到同一句或前文中的明確依據；不能用後一句才補出的資訊替前一句取得使用資格。

- 讀者第一次得知某個症狀、習慣、關係或規律時，先用中性寫法建立事實，再在後文自然使用「又／再次／依舊」。

- 「果然」還要求 POV 角色先有可辨識的預期；作者知道答案不等於角色已經預期。

- 並列結構「又 X 又 Y」與選擇問句「A 還是 B」不屬於本規則的前情用法，不得因關鍵字命中而誤判。

- 這些詞不是禁詞。前提成立、角色語氣自然、句子確實需要時可以使用。

## 6C｜AI 高頻生成模式

- 模糊感官比喻：胸口像被壓住、空氣像凝固、時間像停住、情緒像潮水、腦中像有弦斷掉。

- 固定微表情與固定動作：瞳孔一縮、指尖微蜷、喉結滾動、唇角勾起、視線落到某物後停住。

- 概念摘要模板：「不是 X，而是 Y」「真正的原因是」「這意味著」「某種情緒在心底蔓延」。

- 作者重複解釋：前面已用動作或對話演出，後面又補一句抽象總結。

- 攝影機式敘述：先掃光線、聲音、窗外、桌面，再讓人物開始做事，但那些細節沒有功能。

- 通用段尾餘韻：沉默落下、空氣安靜、某種東西改變了、誰都沒有再說話，卻沒有具體後果。

- 碎句製造假張力：把正常完整句拆成數個兩到八字段落。

命中上述模式時，先判斷句子在場景中的功能，再重寫資訊、動作、因果或角色聲音。不得只換同義詞，也不得把一個新句型機械套到全文。

# 7｜DETAILS ＆ SCENE DENSITY

7.1 每個特別寫出的細節至少服務一件事：推事件、交代必要空間、顯示人物習慣、改變判斷、承接情緒、製造因果或埋伏筆。

7.2 禁止攝影機掃房間。冷氣、風扇、車聲、燈光、窗外等不能只是為了「有畫面」一起列出。

7.3 禁止說明文式背景打包。過去發生的事，只有當角色現在真的會想到或用到時才進場。

7.4 細膩不等於寫滿。刪掉某個細節後，場景、人物、因果、節奏完全沒差，就優先刪。

7.5 不要把同一件事說兩次。前面已經演出來，後面不要再抽象總結。

7.6 每個主要場景至少讓讀者站得住：知道人在哪、正在做什麼、想完成什麼、出了什麼變化。

7.7 重要事件必須真的發生，不可只寫「於是他們爭吵／後來關係變差」這種摘要。

# 13｜HARD FAIL CODES

- SCENE-02：細節是裝飾或攝影機清單，刪掉完全沒差。

- STYLE-01：抽象情緒、哲理句、文藝句把簡單意思繞遠。

- STYLE-02：大量一句一段、兩到八字碎句或連續同句式。

- STYLE-03：作者直接評論角色「其實、單純、沒有掙扎、真正原因是」。

- POV-01：第一人稱連續「我……我……我……」或大量「我看到／我覺得／我知道」外殼。

- POV-02：同一場景跳進另一個人的內心。

- VOICE-01：遮掉名字後，各 POV／台詞聽起來像同一個人。

- DIALOG-01：一句台詞把動機、情緒、價值觀、本場主題全部講完。

- DIALOG-02：角色把潛台詞直接解釋給讀者。

- ERA-01：穿越後稱謂、階級、場合不合。

- ERA-02：現代制度／網路詞穿幫，或假古風／日翻敬語過量。

# 14｜FINAL QA ＆ COLD READ

完成一章後依順序檢查：

- STRUCTURE：場景有開始、變化、選擇、結果嗎？角色真的想做一件事嗎？

- CLARITY：第一次讀就知道人在哪、在做什麼、為什麼改變做法嗎？

- PROSE：是自然白話中文嗎？句型有伸縮嗎？有沒有碎句或「我」過量？

- DETAIL：每個被特寫的細節都有用嗎？

- DIALOGUE：真人在這個場合會這樣說嗎？是否把潛台詞講破？

- CHARACTER：像這個角色本人嗎？把名字遮掉後仍有差異嗎？

- ERA：稱謂、階級、年齡、職業與世界用語正確嗎？

- TERMS：異世界牧師／神官／聖職體系的層級、現代醫療詞、人名與頭銜是否一致？

- CONTINUITY：是否違反人物 Bible、06 關係矩陣、世界底層設定與目前有效的新主線／場景卡？

- AI：有沒有模板句、作者解說感、過度小說化、固定微表情或重複段尾？

- FORMAT：章名、章節分頁、空行、全形標點、引號、編碼與換行是否保留且一致？
